## Frozen pick field structure

PredictionVersion defines all 9 frozen pick fields as Optional with default None:

- selected_market: market identifier (e.g., "HOME_WIN", "OVER_2_5")
- selection_text: human-readable text (e.g., "Home Win", "Over 2.5 Goals")
- selection_probability: model probability [0, 1]
- selection_confidence: confidence score [0, 1]
- selection_odds: bookmaker odds at prediction time
- selection_fair_odds: fair odds from model probability
- selection_edge: edge over bookmaker (probability - implied probability)
- value_classification: "STRONG_VALUE", "VALUE", "NEUTRAL", "NEGATIVE_VALUE"
- risk_level: "LOW", "MEDIUM", "HIGH"

The field names map directly to the BestTip dict keys from the Smart Market Selector, with one exception: `bookmaker_odds` in BestTip becomes `selection_odds` in the frozen pick, which is semantically clearer (the odds associated with the selection).

## BestTip vs PassDecision handling

The create_version() method distinguishes between BestTip and PassDecision dicts by checking for the `pass_decision` key. When `pass_decision` is not True and the `market` key exists, the method populates the frozen pick fields from the dict. When `pass_decision` is True, all frozen fields remain None. This correctly represents that no selection was made for a PASS.

The implementation handles the case where mensione_pick is None (early stage predictions before Smart Market Selector runs) by leaving all frozen fields as None.

## Result tracking field structure

Three result tracking fields are defined with default None:

- actual_result: outcome string ("WON", "LOST", "PUSH", "VOID")
- profit_loss: profit/loss in units (e.g., +0.85, -1.00)
- settled_at: timestamp when result was recorded

The tests verify these fields remain None after create_version(). No test fabricates values for these fields, correctly representing that the result ingestion pipeline does not yet exist.
