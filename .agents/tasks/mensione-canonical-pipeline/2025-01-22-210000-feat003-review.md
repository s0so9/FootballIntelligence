# SmartMarketSelector integration into canonical pipeline

The FEAT-003 integration replaces MensionePickGenerator with SmartMarketSelector in the PredictionService canonical pipeline. The integration correctly calls evaluate_and_select() with market_probs, confidence_assessment, odds_data, and pipeline_version. Both BestTip and PassDecision dataclass outputs are converted to dicts with all required fields, preserving the mensione_pick variable name for downstream use. The API docstring documents the dual structure (BestTip when qualifying market found, PassDecision when no market qualifies). Integration tests verify both output formats.

**Watch for:** None — the integration is complete and correct.

**Verdict**: APPROVED

## High-level view

SmartMarketSelector is instantiated in __init__ with thresholds (min_confidence=0.4, min_probability=0.5, min_edge=0.0, max_risk_level="HIGH"). In generate_full_prediction(), Step 8 invokes evaluate_and_select() after market derivation, passing the four required parameters. The result (BestTip or PassDecision) is converted to a dict using isinstance() checks — BestTip yields a 17-field dict with pass_decision=False, PassDecision yields a 6-field dict with pass_decision=True. Both include timestamp converted to ISO string. The dict is assigned to the mensione_pick variable, which flows into AnalysisContext. The API endpoint docstring documents both structures with field lists and semantic descriptions. The integration test checks for either structure using conditional assertions. One latent bug: market_probs.match_id is not set before evaluate_and_select() is called, so mensione_pick will contain match_id=None.
