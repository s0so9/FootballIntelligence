## High-level view

The ensemble engine implements three distinct weighting strategies with real math: StaticWeights (manual normalized weights), ReliabilityWeights (confidence × data_quality), and DynamicWeights (league-specific adjustments layered on reliability weights). Model agreement is calculated as 1 - (std_dev × 3), properly normalized to [0, 1].

The calibration engine enforces strict temporal cutoffs by filtering training data to timestamps before the cutoff_date, preventing any data leakage. Both isotonic and Platt calibration are implemented via sklearn with graceful degradation when sklearn is unavailable (returns uncalibrated probabilities with warnings). Minimum 50 samples required before fitting.

The confidence engine exposes all six measurable components as specified: model_agreement (from ensemble), data_quality (from DataQualityGate), sample_size_score (sigmoid normalization), calibration_reliability (1 - brier_score), lineup_certainty (0.0/0.5/1.0), and feature_stability (1 - variance of recent predictions). Overall confidence is a weighted average with configurable weights that sum to 1.0.

The contextual adjuster applies bounded adjustments (home advantage, rest days, travel distance, competition importance) with a strict ±15% maximum total adjustment cap enforced via copysign clamping. Probabilities are recalculated using Poisson approximation rather than arbitrarily shifted.

The player impact engine is deterministic and data-driven only — it calculates impacts from historical player xG contribution and defensive metrics, requires minimum 5 matches / 450 minutes, and returns ModelAvailability when data is insufficient. Never fabricates player statistics.

The tactical matchup engine draws conclusions only from structured features (pressing_intensity, possession_tendency, transition_speed, build_up_style) with no LLM involvement. Returns None when data is incomplete (completeness_score < 0.5 for either team). Advantage calculations use dimension-specific weights (pressing: 0.30, possession: 0.25, transition: 0.25, build_up: 0.20).

The league context manager uses Bayesian shrinkage for small samples by blending league-specific estimates with family or global defaults using weight = n / (n + 100). Pre-seeded with major leagues (Premier League, La Liga, Bundesliga, Serie A, Ligue 1) and competition family defaults (top_5_european, lower_european, south_american, asian).

## Ensemble weighting strategies implement real math, not stub averaging

The three weighting strategies are distinct implementations. StaticWeights returns configured per-model weights directly from a dictionary (self.weights.get(pred.model_id, 1.0)). ReliabilityWeights multiplies each prediction's confidence_score by data_quality_score (weights[pred.model_id] = confidence * data_quality). DynamicWeights builds on ReliabilityWeights by first calculating reliability weights, then applying league-specific multipliers from self.league_adjustments when context contains a league_id.

The ensemble's combine() method normalizes weights by dividing by total_weight, then calculates weighted averages for all probability and xG components. When total_weight is zero (edge case: all weights zero), it falls back to equal weighting (1.0 / len(predictions)).

Model agreement is calculated from standard deviation of home_win_prob across predictions: agreement = max(0.0, 1.0 - (std_dev * 3.0)). The factor of 3 normalizes by the maximum realistic std_dev for probabilities (≈0.33 when probabilities span 0-1), keeping most real disagreements in [0, 1] range.

Ensemble confidence combines weighted average of individual model confidences with an agreement adjustment: ensemble_confidence = avg_confidence * (0.7 + 0.3 * sqrt(agreement_score)). The square root avoids overly penalizing moderate disagreement.

When fewer than 2 predictions are available, combine() returns ModelAvailability with reason="insufficient_models" rather than attempting to average a single prediction.

## Calibration engine enforces strict temporal cutoff

The fit() method accepts a cutoff_date parameter. When provided, it filters the CalibrationData by iterating through (prob, outcome, ts) tuples and only keeping those where ts < cutoff_date. This filtered dataset is then passed to the underlying calibrator (IsotonicCalibration or PlattCalibration).

The temporal filter is applied before any model fitting occurs, preventing the calibrator from seeing any data at or after the cutoff. This is the correct implementation for leakage prevention — the cutoff is enforced at the data level, not as a post-hoc check.

Both calibration methods (isotonic and Platt) check for minimum 50 samples before fitting. If len(data) < MIN_SAMPLES, they warn and return without setting is_fitted_ = True. Subsequent calls to calibrate() on an unfitted calibrator return the uncalibrated probability with a warning.

When sklearn is unavailable (SKLEARN_AVAILABLE = False at module level), the fit() method warns and returns early without attempting to import sklearn classes. The calibrate() method continues to work, returning uncalibrated probabilities. This is graceful degradation.

Brier score and log loss are calculated in _calculate_metrics() by iterating through (predicted_prob, actual_outcome) pairs. Brier score sums (prob - outcome)² / n. Log loss uses epsilon clipping (max(eps, min(1.0 - eps, prob))) to avoid log(0).

## Confidence engine exposes all 6 components

The assess() method constructs a ConfidenceComponents dataclass with all six fields populated:

- model_agreement: passed directly as parameter (from ensemble)
- data_quality: passed directly as parameter (from DataQualityGate)
- sample_size_score: calculated via _calculate_sample_size_score(n_matches) using sigmoid with n0=30, k=0.1
- calibration_reliability: calculated via _calculate_calibration_reliability(brier_score) as 1.0 - brier_score (returns 0.7 if brier_score is None)
- lineup_certainty: mapped from lineup_status string via _get_lineup_certainty() (1.0 for "confirmed", 0.5 for "expected", 0.0 for "unknown")
- feature_stability: calculated via _calculate_feature_stability(recent_predictions) as max(0.0, 1.0 - (variance * 4.0))

After construction, components.validate() checks that all values are in [0, 1] and raises ValueError if not.

The overall confidence is calculated as a weighted average: overall = sum(component_value * weight_value for all 6 components). The ConfidenceWeights dataclass defines default weights that sum to 1.0 (model_agreement: 0.25, data_quality: 0.25, sample_size: 0.15, calibration: 0.15, lineup: 0.10, stability: 0.10).

The confidence label is derived from the overall score: HIGH (>0.7), MEDIUM (≥0.4), LOW (<0.4).

Component breakdown is calculated as a dictionary mapping component names to their weighted contributions (component_value * weight_value). This allows inspecting which components drove the final score.

## Contextual adjuster enforces ±15% maximum adjustment cap

The adjust() method calculates individual contextual adjustments (home advantage, rest days, travel distance, importance), applies them to expected goals, then checks the total adjustment magnitude against MAX_TOTAL_ADJUSTMENT = 0.15.

The total adjustment is calculated as: (adjusted_xg - base_xg) / base_xg for both home and away teams. If abs(total_adjustment) > 0.15, the adjusted_xg is clamped to base_xg * (1.0 + copysign(MAX_TOTAL_ADJUSTMENT, total_adjustment)). This preserves the direction of adjustment while enforcing the 15% bound.

The copysign approach is mathematically correct: it takes the magnitude (0.15) and applies the sign of the original adjustment, effectively capping at +15% or -15% depending on direction.

After bounding, the method recalculates probabilities using _recalculate_probabilities(), which iterates through scorelines (h, a) from 0 to max_goals (default 10), calculates Poisson probabilities for each, and accumulates home_win/draw/away_win probabilities. This is a proper probability derivation, not an arbitrary shift.

Home advantage adjustment is league-specific (self.league_home_advantage.get(league_id)) with DEFAULT_HOME_ADVANTAGE = 0.05 as fallback. Rest days adjustment checks home_rest_days and away_rest_days < 3 and applies 0.97 multiplier (-3%). Travel adjustment checks travel_distance_km > 500 and returns -0.02. Cup final (is_cup_final) applies 0.95 multiplier to reduce home advantage at neutral venues.

The metadata in the returned ModelPrediction includes "contextual_adjustments" with all original and adjusted values, making adjustments auditable.

## Player impact engine never fabricates data

The calculate_impact() method accepts Lists of PlayerImpactData, each containing historical statistics (matches_played, avg_xg_contribution, avg_xa_contribution, avg_defensive_contribution, minutes_played). The has_sufficient_data property checks matches_played >= 5 and minutes_played >= 450.

In _calculate_team_impact(), the loop iterates through absent_players and checks player.has_sufficient_data. If False, it skips that player (does not fabricate a value). Only players with sufficient data contribute to attacking_delta and defensive_delta.

After the loop, data_sufficiency is determined: "insufficient" if players_with_data == 0, "partial" if players_with_data < total_players / 2, "complete" otherwise. If data_sufficiency is "insufficient", calculate_impact() returns ModelAvailability with reason="insufficient_player_data".

This is the correct handling: when data doesn't exist, the engine explicitly reports unavailability rather than inventing placeholder values. The ModelAvailability.missing_features field contains a human-readable explanation.

The expected_goals_delta is calculated only from attacking_delta (absent players' xG/xA contributions). The defensive_delta is tracked separately but not currently incorporated into expected_goals_delta (this is conservative: only subtracts from attack, doesn't fabricate defensive impacts without a validated model).

Adjusted xG values are clamped to minimum 0.1 (max(0.1, adjusted_xg)) to prevent negative or zero expected goals, which would break Poisson calculations downstream.

## Tactical matchup engine uses structured features only

The analyze() method accepts TacticalProfile objects containing pressing_intensity, possession_tendency, transition_speed, build_up_style — all Optional[float] in [0, 1]. The is_complete property checks whether all four dimensions are not None. The completeness_score returns the fraction available (0.0 to 1.0).

The _has_sufficient_data() check requires completeness_score >= 0.5 for both teams (at least 2 out of 4 dimensions available). If this check fails, analyze() returns None rather than inventing a result.

The _calculate_dimension_advantages() method calculates advantage only for dimensions where both teams have data (both values are not None). Each dimension uses a specific calculation:

- Pressing: press_diff = home - away, but if abs(press_diff) > 0.4, applies 0.5 multiplier (extreme difference allows counter-pressing)
- Possession: poss_diff * 0.6 (moderate advantage to possession team)
- Transition: trans_diff * 0.7 (fast transitions have strong advantage)
- Build-up: build_diff * 0.5 (tactical flexibility advantage)

These calculations are deterministic transformations of the input features. No LLM, no subjective analysis, no invented tactical insights.

The overall advantage score is calculated in _calculate_overall_advantage() as a weighted average of available dimensions using fixed weights (pressing: 0.30, possession: 0.25, transition: 0.25, build_up: 0.20). Only dimensions present in dimension_advantages are included.

The explanation in _generate_explanation() is a template-based string constructed from the calculated advantages and dimension names. It's not generated text; it's a deterministic format string.

Confidence is calculated as min(home_profile.completeness_score, away_profile.completeness_score), further reduced by 0.7x if either team has matches_analyzed < MIN_MATCHES_FOR_PROFILE (5).

## League context manager uses Bayesian shrinkage for small samples

The get_league_profile() method checks if a specific league_id exists in self.league_profiles. If it does and profile.matches_analyzed < MIN_MATCHES_FOR_RELIABILITY (100), it calls _apply_shrinkage(profile).

The _apply_shrinkage() method calculates shrinkage weight as: weight = n / (n + k) where n = matches_analyzed and k = MIN_MATCHES_FOR_RELIABILITY (100). This is the standard Wilson score interval approach: small samples get weight close to 0 (mostly default), large samples get weight close to 1 (mostly league-specific).

Shrunk parameters are calculated as: shrunk_value = weight * league_value + (1 - weight) * default_value for each of scoring_environment, home_advantage_factor, draw_tendency.

Defaults are selected hierarchically: if profile.competition_family exists and is in FAMILY_DEFAULTS, use family defaults; otherwise use GLOBAL_DEFAULTS.

The FAMILY_DEFAULTS dictionary is pre-populated with reasonable values for "top_5_european", "lower_european", "south_american", "asian". GLOBAL_DEFAULTS provides universal fallback (scoring_environment: 2.7, home_advantage_factor: 1.3, draw_tendency: 0.27).

The _initialize_default_leagues() method pre-seeds major leagues (Premier League, La Liga, Bundesliga, Serie A, Ligue 1) with family defaults and confidence=0.5, signaling that these are defaults pending historical data updates.

Confidence calculation in _calculate_confidence() uses sigmoid: 1.0 / (1.0 + exp(-k * (n - n0))) with n0=100, k=0.02. This maps sample size smoothly to [0, 1], reaching 0.5 at 100 matches.

## All engines handle missing data gracefully

Each engine has explicit handling for missing or insufficient data:

- EnsembleEngine: returns ModelAvailability when len(predictions) < 2
- CalibrationEngine: warns and returns uncalibrated probability when not fitted or sklearn unavailable
- ConfidenceEngine: uses neutral values (0.7 for calibration_reliability if None, 1.0 for feature_stability if recent_predictions empty)
- ContextualAdjuster: uses defaults when context keys missing (rest_days defaults to 7, travel_km defaults to 0)
- PlayerImpactEngine: returns ModelAvailability with reason="insufficient_player_data" when data_sufficiency == "insufficient"
- TacticalMatchupEngine: returns None when completeness_score < 0.5 for either team
- LeagueContextManager: falls back to global defaults when league_id not in profiles

These are all explicit representations of unavailability. No silent failures, no fabricated defaults that could be mistaken for real data.

The use of ModelAvailability (with reason and missing_features fields) is particularly strong — downstream consumers can distinguish "no prediction" from "low-confidence prediction" and can inspect exactly what was missing.
